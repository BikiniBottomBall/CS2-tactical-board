# P8 局域网分享 + P9 多人协同

## TL;DR

> **目标**：P8 实现战术板局域网链接分享（只读视图），P9 实现多人实时协同（WebSocket 房间）。PostgreSQL 迁移已在 P8 前置完成。
>
> **核心思路**：操作同步（Operation Sync）——服务端接收操作消息 → 合并冲突 → 广播，不做 OT/CRDT。轻量匿名鉴权（HMAC 签名 token + 昵称）。
>
> **预估**：P8 1-2 天，P9 8-12 天，总计 9-14 天。
> **并行度**：中（P8 可全并行，P9 分波次但前端 board/tactic 改造串行依赖 sync.ts）。

## Work Objectives

### Core Objective
为 CS2 战术板添加**局域网链接分享**（P8）和**房间制多人实时协同**（P9），保持现有单人模式完全兼容。

### Concrete Deliverables

**P8（局域网分享）：**
- `GET /view/{share_id}` — 只读战术板页面，任何人通过链接可查看
- 战术包分享链接生成（基于已有 P6 导出格式）
- 分享页面：纯 Three.js 渲染，禁用编辑，可旋转缩放

**P9（多人协同）：**
- `POST /api/rooms` — 创建房间，返回 6 位房间码
- `ws://host:8000/ws/{room_code}` — WebSocket 房间消息通道
- `network.ts` — 前端 WebSocket 连接管理
- `sync.ts` — 操作同步适配层
- room_manager.py — 服务端房间内存管理
- auth.py — HMAC 签名匿名 token
- 3 张新表：users / rooms / room_members
- 远程光标渲染 + 在线成员列表
- 锁系统（战术播放/道具录入独占）

### Must Have
- [ ] P8：分享链接可打开只读战术板
- [ ] P9：2+ 人可在同一房间实时协作（标记、线、演员拖拽）
- [ ] P9：战术播放锁（只有一人能控制播放）
- [ ] P9：道具录入锁（只有一人能同时录入）
- [ ] P9：每人独立撤销栈
- [ ] 单人模式零退化（localStorage 路径保留）

### Must NOT Have
- [ ] 用户注册/密码/邮箱验证（匿名 token 足够）
- [ ] 消息持久化历史（房间关闭即清）
- [ ] 离线编辑
- [ ] 实时语音/文字聊天
- [ ] 权限细分（只有房主 vs 成员）
- [ ] 移动端适配
- [ ] OT/CRDT 冲突算法（操作同步 + 后到覆盖足够）
- [ ] `@ts-nocheck` 添加到新模块（network.ts / sync.ts 必须类型安全）
- [ ] 删除 `markerScale` 的 localStorage 持久化（被 grid/tactic 引用）
