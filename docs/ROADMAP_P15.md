# CS2 战术板 · P15 公开上线计划（2026-08-06）

> 目标：把 P0~P13 的「个人工具」升级为可公开运营的 Web 产品。
> 核心判断：公开上线不等于堆新功能，而是补齐四块短板——**账号体系、内容归属、安全加固、部署运维**。

## 一、现状与差距

已完成（P0~P13）：真实 3D 战术板、道具库、战术编排、战术包分享、demo 回放、多人协同、工程化（pytest / CI / ruff / black / 配置管理）。

当前仍是个人工具形态：

| 维度 | 现状 | 上线差距 |
|---|---|---|
| 账号 | 匿名 HMAC token，无注册/登录 | 需完整账号体系 |
| 内容 | 全表全局可见，无作者概念 | 需归属与可见性控制 |
| 安全 | 默认密钥、上传无限制、无限流 | 需安全加固 |
| 部署 | 本机 SQLite、`data/` 未挂卷 | 需服务器部署 + 持久化 |

## 二、前置：P14 功能打磨（先优化后上线）

主要功能仍粗糙，上线前需打磨（方向清单，细节另行细化排期）：

- 道具库：录入交互、轨迹预览、落地效果、播放反馈
- 战术编排：步骤编辑、演员拖拽、推演流畅度与同步
- demo 回放：性能、进度交互、书签跳转、kill feed 细节
- 3D 场景：45MB 模型加载速度、同屏效果性能（≤4 特效 60fps）
- UI/UX 统一：毛玻璃面板样式、操作提示、空态/加载态
- 移动端基础适配（可选，先摸清目标用户设备）

## 三、P15 公开上线最小闭环

### 1. 账号体系（地基，最先做）

- `users` 表扩展：`email`、`password_hash`（bcrypt）、`avatar`、`role`（user/admin）
- 注册 / 登录 / 登出 + 会话 token；保留现有 HMAC 匿名逻辑给多人房间
- MVP 用邮箱+密码（可控、易做找回）；Steam OAuth 放到 P16
- 涉及：`models.py` + Alembic 迁移、`auth.py`、`schemas.py`、`app.py`

### 2. 内容归属与可见性（改动量最大）

- `utilities` / `tactics` 增加 `author_id`、`is_public` 字段
- 全部相关 API 权限化：私有内容仅作者可读写，公开内容全局只读
- 分享链接复用现有机制，公开内容可直接分享
- 涉及：`app.py` 中全部 utilities / tactics / annotations 接口

### 3. 社区基本盘

- 搜索与筛选：后端加 `type/category/tag/keyword` 查询参数，前端加搜索框与筛选侧栏
- 点赞 / 收藏表（新增 favorites / likes）
- 作者主页：该作者公开的 lineup 与战术列表
- 道具/战术数据模型补充：`category`、`tags`、`usage_count`、`rating`、`video_ref`

### 4. 部署上线

- Nginx 反代 + HTTPS（Let's Encrypt）+ 域名
- 生产切 PostgreSQL（docker-compose 已就绪）
- **`data/` 目录挂持久卷**：模型（45MB）与 demo（276MB）不能随容器重建丢失——当前 compose 只挂了 `pgdata`，必须补
- CI/CD：GitHub Actions 测试通过 → 自动构建镜像 → 服务器部署
- **保持 uvicorn 单进程**：房间状态在进程内存（`room_manager.py`），不可用多 worker，MVP 规模无需 Redis

### 5. 安全红线（上线前必须完成）

- `BOARD_SECRET` 换生产密钥（当前默认 `dev-secret-change-me`）
- demo 上传加大小限制与文件类型校验（当前无上限）
- 登录 / 创建 / 上传接口限流
- `/healthz` 健康检查 + 日志轮转
- 依赖漏洞扫描（可选，CI 加一步）

## 四、上线后迭代（P16+）

- 内容审核：举报 + 管理员下架（`role` 字段先埋好）
- 热度排序与首页内容流（收藏/播放量）
- 统计埋点：公开内容播放量、收藏量
- 运营后台（简单 admin 页面）
- Steam OAuth 登录
- 大文件存储外置：对象存储（S3 / OSS / COS）承载模型与 demo

## 五、技术决策记录

- 保持单进程 uvicorn，不引入 Redis（MVP 规模足够；将来扩展再考虑 Redis pub/sub 跨实例广播）
- SQLite 仅限开发，生产一律 PostgreSQL，schema 无方言可平迁
- 文件存储先 `data/` 持久卷，量级上来后切对象存储
- 3D 玩法（战术板 / 回放 / 房间）保持现状，MVP 重心放在内容可发现、可运营
- 不引入 React/Vue/微服务，维持现有 Three.js + Vite + FastAPI 栈

## 六、待决策项

- [ ] 登录方式：邮箱+密码（推荐 MVP）还是优先接 Steam OAuth
- [ ] 服务器与域名资源是否已具备（决定部署章节如何落地）
- [ ] 境内服务器公开站点是否需要 ICP 备案
- [ ] P14 功能打磨的具体范围与排期

## 七、验收标准（P15）

- 注册/登录可用；内容按作者归属；私有内容他人不可读写
- 公开内容可搜索、可收藏；作者主页可访问
- 生产环境 HTTPS 可访问；PostgreSQL 迁移自动执行；`data/` 持久化
- 上传与接口限流生效；生产密钥非默认值
- 本地与生产功能回归通过（pytest + 前端构建）
